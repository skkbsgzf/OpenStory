# 数据分析模块（openstory_analysis_chapter）

分析引擎是**纯本地计算**：零模型调用、零网络、秒回。全部指标基于文本本身且可解释——每个数字都能指到具体的词/句。这是它和「让 LLM 点评」的本质区别：同一文本结果恒定，可以做改写前后的**对照实验**。

## 工具

| 工具 | 输入 | 输出 |
|---|---|---|
| `openstory_analysis_chapter` | `text`（正文 md 源文） | stats / rhythm / emotion / style / aiSmell / issues |

## 五个维度怎么读

**stats**：字数、段数、平均句长、对白比例。对白比例异常低＝叙述过载；平均句长超过 40＋＝阅读负担重。

**rhythm**：逐段字数序列。健康节奏是锯齿状起伏——连续等长段落＝「段落过于均匀」（AI 味核心信号）。

**emotion**：逐段情绪强度（正负词典密度）。置信度依赖文本长度：短文会如实给低置信。曲线的峰值/谷底对应情绪转折点。

**style**：
- `sentenceCv`（句长变异系数）：**人写的句子长短参差**。≥0.55 参差自然；0.35–0.55 偏整齐；<0.35 过于均匀（模板感）。
- `paraCv`（段长变异系数）：同上，段级。≥0.5 自然。
- `cliches` / `connectives`：套话与连接词命中清单（每个都带次数与段落定位）——**直接可改**。

**aiSmell**：四因子加权评分（套话密度/连接词堆砌/句式过于整齐/段落过于均匀），0–100。<25 好，25–50 警惕，>50 模板文。每个因子都带「多少处、什么阈值」——不是玄学分数。

**issues**：可定位到段落的问题清单（`paragraphs` 字段给出段号，severity 分 high/medium/low）。改写时按段号逐个处理。

## 标准用法：改写对照实验

```
1. openstory_novel_read_chapter {root, file}      → 原文
2. openstory_analysis_chapter {text: 原文}        → 基线（记下 aiSmell.score 与 issues）
3. 改写
4. openstory_analysis_chapter {text: 改写稿}       → 对照
5. aiSmell 下降 + 句长 paraCv 上升 = 改写有效
```

这比「让模型自己说改好了」可信——指标是词典与统计算的，不诚实无法伪装。

## 置信度

引擎对短文本（<300 字）会降低置信：情绪词典命中少、节奏序列太短。issues 照出，但解读时应把「低置信」放在心里。置信度在 `result.stats` 里没有独立字段——按文本长度自行判断，或对照 OpenStory 界面里「本章偏短，指标仅供参考」的同一阈值。

## 与其它模块的勾连

- 小说：读正文 → 分析 → 改写 → 再分析（见 novel.md 的改写流）
- 推演：`openstory_fact_curve` 是**章级**的剧情曲线（需要事实链数据）；本章分析是**段级**的文本体检——粒度不同，配合用。
