# OpenStory 演示脚本

> 唯一演示库是仓库自带的《水浒传》，覆盖长篇正文、世界书、故事源、扮演与本地分析：
>
> | 库 | 载体 | 用途 |
> |---|---|---|
> | **水浒传**（`samples/水浒传/`） | novel | 长篇：正文、世界书图谱、故事源三形态、扮演文游 |
>
> 在仓根启动：`npm start`（daemon 127.0.0.1:8807），浏览器打开 `http://127.0.0.1:8807`。
> MCP：`npm run mcp`（前置同 daemon）。
>
> `samples/水浒传/` 是免登记的体验库：它带 `.openstory/ui-state.json` 与
> `.openstory/plugins/suite-state.json`（由 MCP-only 构建链生成），拷贝或导入后打开即复现
> 一份配置好的工作台，不必重设页签与套件。
>
> 说明：本样本由 `tools/verify/verify-shuihu-10ch.mjs` 从空目录经 113 次真实 MCP 调用重建
> （`--recipe-10ch`）。业务内容来自 `tools/samples/shuihu-input/`（第 1 回）与
> `tools/samples/shuihu-input-10ch/`（第 2–10 回）的受控配方；**唯一事实源＝前 10 回的
> 39 条 `fact.data/v3` 条目＋wiki 派生层**，正文只作逐字出处（FACT-FIRST）。
> 主档与 wiki revision 一致，gold query 见 `knowledge-packs/shuihu-10ch/gold.json`。
> clean-room 使用假文本上游验证协议与落盘，**不 BYOK、不声称真实 enrich/扮演/识图/生图或语义检索质量通过**
> （`semanticModelVerified:false`）。复现与回滚见 `samples/水浒传/README.md`。

## 一、正文（纯净写作面）
顶栏选《水浒传》→ 页签「正文」。
- **第 1–10 回**完整正文（回目对偶、宋明白话；唯一事实源是事实链，正文只作逐字出处），
  右侧分析面板：**编辑总评**（人话结论＋好在哪＋问题在哪＋改法＋定位/详情跳转）、
  情绪曲线、文风变异系数、AI 味、本段批注。
- 习惯表驱动：禁用词「忽然」会在第 11 段被标出（依据＝本库习惯表）。

## 二、世界书（创作型条目库）
页签「世界书」：默认进**全库关系图谱**；左侧标签树按层级筛选；点笔记看详情＋双段反链。
- 18 篇条目（人物 6/场景 4/事件 2/大纲/约束→已迁习惯/资料…）、15 个标签（含描述）。
- 注意：规则类内容已移到「习惯」——世界书只管条目。

## 三、习惯（写作习惯表）
页签「习惯」：描述性自定义表单。
- 口吻（直言/温和）、文风自述、禁用词（心理活动/压力/效率/忽然）、惯用词（那厮/恁地…）、
  禁用句式、禁用修辞、喜好的描述公式。
- **Agent 成文前强制注入**；分析引擎按它扫描（改禁用词列表 → 重新分析 → 问题随之变化）。

## 四、扮演（文游体验）
页签「扮演」→ 引擎模式：
1. **当前局面**：场景立绘铺满（占位渐变，放 `扮演/shuihu/素材/场景/龙虎山.png` 即换真图——
   已有示范）、右侧人物头像列（洪信/范仲淹有立绘）、顶部张力徽标＋BGM 开关（`素材/bgm/平静.mp3`）。
2. 候选区：命运骰候选（带检定翻译与人话解释）＋「自己写」输入框。
3. 「走这条」→ DSH 子 agent 以小说叙述体生成 200–400 字正文进对话框；草稿**就地编辑**
   （✎ 编辑/✓ 收起切换），动作行 [↻ 重写][下一拍 →] 内嵌对话框右上。
4. 「下一拍」推进；「本章缓冲 X 拍 Y 字」实时可见；「归档本章」整理成
   `扮演/shuihu/归档/第1章.md`（已有示范：三拍 1046 字）。
5. **剧情树**子页签：横轴拍号、纵轴分支泳道、分叉虚线、点节点回跳／开新分支。
6. 舞台左上「局面＋事实包」浮层卡（顶栏「局面」可收起）：张力/钩子/地点缺什么如实列；
   「⚙ 设置」弹层收 POV/种子/推进/重新开局。

## 五、分析（本地引擎，秒回）
正文页右上 ⏱ 图标。全部规则可溯源（每条结论带「依据：…」）：
- 节奏平坦（连续等长段）、对白比例、句长/段长变异系数、套话与连接词（带段落定位）、
  开篇钩子（读者需求铁律）、AI 味四因子。
- 阈值来自 fanqie-pattern-playbook / de-ai-writing / shuangwen-chapter-check / reader-needs-ironrules。

## 六、故事源（Fact 链的三形态）
页签「故事源」（磁盘目录同名 `故事源/`）：
- **大纲态**：左栏 章 → 段 → 条目 三级树（段＝`provenance.segmentIndex`）；中栏按
  `layer` 换渲染器——剧情＝事件流、角色＝台词/行为/内心锚点、世界观＝字段表；
  右栏溯源（`sourceId`＋`segmentId`＋`quote_hash` 缩写）、世界书/人物关联、扮演/分析消费点。
- **表格态**：飞书多维表风格的只读表，列＝名称/层/状态/出场人物/章/段/事件数；
  左栏层筛选、顶部名称搜索、点行选中（不做拖拽与内联编辑）。
- **图表态**：ECharts 走本地 vendor 单文件（`public/vendor/echarts.min.js`，进图表态才按需加载）。
  剧情曲线（张力×事件密度）、伏笔回收（埋/收/未收）、剧情密度热力图（章×段）；
  图色从 `:root` CSS 令牌取，换皮肤自动重绘。ECharts 加载失败时降级为文字表，不白屏。
- **双层对齐**：优先用 `provenance.chapters[0]`；缺失时按 `segmentIndex` 均分到 wiki 章，
  页头标「对齐：精确/近似」。整本条目都标同一章、而 wiki 是多章时自动改走段号均分，
  避免所有条目全挤进「第 1 章」。

## 七、世界书参考图（OS-75）

世界书条目支持**参考图/设定图**，人物单页是角色档案风格：

1. 打开《水浒传》→ 世界书 → 点「林冲」
2. 点「✦ 生成设定图」→ 真调 ComfyUI（约 2–3 分钟）→ 图落 `世界书/人物/assets/`，frontmatter 自动回填 `cover`/`images`
3. 生成后，详情页左侧是大图肖像 + 标签 + 摘要，右侧关系图谱

**看图写作**：`skills/visual-describe` + MCP 工具 `openstory_vision_describe` ——
读参考图，用文学语言写白描（不是技术描述），产出可直接进条目正文，也能当生图提示词底稿。

## 八、生图双后端（OS-74/75）

设置 → 模型 → 生图，支持两种后端：

| 后端 | 配置 | 适合 |
|---|---|---|
| **OpenAI 兼容 API** | endpoint（填到 `/v1`）+ 模型 + key | 云端，一次请求直接出图 |
| **ComfyUI**（本机） | 地址（`http://127.0.0.1:8188`）+ 工作流 JSON + 节点映射 | 本地，可控工作流，免费 |

- 「测试连接」会真发请求：OpenAI 路径发一次最小生成（**会花额度，需确认**），ComfyUI 路径走 `/system_stats` 只读探测。
- ComfyUI 工作流用「Save (API Format)」导出；节点映射留空则按 title 自动猜（Positive/Negative/KSampler/EmptyLatentImage）。

## 九、文字模型与 CLI（OS-74）

设置 → 模型 → 对话模型，三种运行时：

| 运行时 | 模型来源 | 凭据 |
|---|---|---|
| **DSH** | `/api/agent/dsh/models` 实时枚举（带推理深度选项） | DSH 自己的 profile |
| **CLI**（Claude / 编码代理 / 编码代理） | kit manifest 的 `models` 清单 | **CLI 自己登录的凭据——本仓不存 key、不直连 LLM API** |
| **Pi**（兜底） | 手填 endpoint + model | 本仓存 key（脱敏回显） |

CLI 模式的设计意图：跑动记录与 CLI 自己的历史一致，不产生两套账。

## 十、MCP（对外输出）
68 个工具覆盖小说/剧本、世界书、独立知识库、习惯、故事源、建库与套件、exchange、多局与扮演、素材、分析与技能货架（详见 `docs/mcp/OVERVIEW.md`）。
读写分级：读自由；写有 .history 备份；absorb 不开；习惯表有 `openstory_habits_read`。

## 已知边界
- LLM 类能力走当前运行时（DSH 原生）；换 endpoint 型运行时可增强推演候选丰富度。
- 立绘/BGM 素材为占位演示图；替换 `扮演/shuihu/素材/` 下同名文件即换真素材。
- 分支拍的树横轴序号用引擎全局计数（分叉靠虚线指回）——分支本地序号重排是独立迭代项。
