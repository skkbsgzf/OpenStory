## 1. 规划书原文（作者，2026-11-26，逐字）

# OpenStory 插件前端适配说明
> 2026-11-26 整理。范围：OpenStory 插件体系的前端适配现状、待办工作与设置页「插件治理台」设计。数据均来自当前主仓 21 份模块清单的实测。

## 一、架构背景（前端适配的前提）

OpenStory 采用**微内核插件架构**：宿主只保留底座（装载协议、能力图、契约壳、物理写管道），全部产品能力由插件供给。当前共 21 件模块，分三类：

| 类别 | 数量 | 角色 | 可否停用 |
|---|---|---|---|
| 内器件（kernel） | 7 | 能力供给层，无界面：Agent 运行时、事实内核、正文内核、文本内核、推演引擎、媒体引擎、存储内核 | 不可停（下游断链） |
| 工作台（workbench） | 12 | 用户工作面：正文、剧本、世界书、故事源、扮演、分析、生图与识图、知识库、习惯、日志、产物、导入导出 | 可停用，只收工作面、数据保留 |
| 宿主组合面（host） | 2 | 宿主域实现的组合界面：Agent 栏、库管理 | 随宿主走 |

插件间关系由**能力图**约束：每件声明自己「供给」哪些能力（能力 id＋版本，其中带官方实现契约的称为金样能力）、以及「依赖」哪些能力（最低版本）。例：扮演（workbench）依赖 deduce.engine、fact.store@3、prose.write、text.analyze 四项能力，分别由推演引擎、事实内核、正文内核、文本内核供给。

后端对前端的唯一数据面是 `/api/plugins` 投影：页签、右栏面板、设置表单均由投影驱动，前端不再持有插件名单。

## 二、已完成的前端接入

- 页签投影：工作台页签由后端投影生成，前端不再硬编码名单；
- iframe 页：模块自带独立页面可嵌入工作区；
- 套件详情：插件中心主从两栏，覆盖来源、身份、能力、启停、设置表单；
- 本机模块治理：登记 → 预览 → 确认 → 刷新全流程已接，信任说明置顶。

## 三、待适配的工作项（按优先级）

1. 依赖降级的用户可见性（最高优先）：插件「停用即从导航消失」已实现，但「依赖缺失导致降级」时工作台如何显形尚未定义。目标：降级件在页签上**灰显＋悬停解释缺了什么**，而不是无声消失；
2. 设置页插件治理台（详见下节）：用户「找一个插件的设置」目前没有固定入口，插件信息散在设置页、插件中心、本机模块区三处，取数口径不一；
3. 三处取数统一：上述三处统一消费 `/api/plugins` 单一投影；
4. 显示名权威迁移：插件显示名目前仍在前端持有一份，应迁入投影，消除双端重复；
5. 设置页旧分区收敛：按功能域硬编码的十余个分区函数，重构为「宿主设置＋插件治理台」两大域。

## 四、插件治理台设计

### 4.1 定位

设置页分两大域：**宿主设置**（外观、引擎与存储、关于等非插件项，保持现状）＋ 插件治理台（21 件逐插件管理）。治理台不新造数据：能力、依赖、金样、启停状态、设置指路全部来自 `/api/plugins` 投影，后端只需补三个推导字段（依赖逐条解析状态、反向依赖、降级态）。

### 4.2 页面结构（极简代码示意，无样式）

```text
设置页
├─ 导航
│ ├─ 宿主设置：外观 · 引擎与存储 · 关于
│ └─ 插件中心：插件治理台 · 面板 · 全部套件 · 本机模块
└─ 插件治理台（主区）
   ├─ 能力图（SVG）：21 节点 + 依赖边；点节点 → 定位对应卡片并高亮其依赖关系
   └─ 卡片流（双列）
      ├─ 内器件 ×7（只读卡）
      ├─ 工作台 ×12（可启停卡）
      └─ 宿主组合面 ×2（身份说明卡）
```

### 4.4 交互规则

- 启停确认列影响面：停用工作台前展示断链清单与数据保留说明，确认后投影即时刷新；
- 「不可停」可解释：内器件开关禁用，点开即见「谁依赖我」与连锁断链清单；
- 设置一律指路：插件不带独立设置项时，卡片显示指路文案＋跳转按钮（真配置在引擎与存储等宿主设置域，避免第二份配置入口）；
- 降级灰显：依赖缺失的工作台在页签灰显＋悬停列出缺失项（与治理台同源数据）；
- 「模块」词义收敛：治理台只管 21 件模块；左右栏 UI 面板插拔独立为「面板」入口；动态装载的可执行件归「本机模块」——三个概念各归其位。

### 4.5 能力图总览

页面顶部提供全局依赖图：节点为 21 件模块（按三类着色），有向边为能力依赖（依赖方 → 供给方），全员依赖的底座能力折叠为一条说明。点击任一节点，图中只保留该件的依赖与反向依赖边，并滚动定位到对应卡片。能力图是插件架构第一次以可视化形式呈现给用户：「谁依赖谁」一图见底。

## 4. 监督线核实出的实况（2026-11-26，HEAD `030dd37`）

规划书的数字全部对得上实测；下面是与实况有出入、决定了工单怎么写的几处。

1. **降级态后端已算好，是前端丢掉的**：`/api/plugins.capabilityReport` 带 `loaded/degraded/disabled/routes/issues`，前端 `loadPlugins()` 没留；`modules[]` 里没有 `requires/capabilities`，启停态前端自己从库内 ui-state 拼。
2. **降级的现状是「页签照常在、点进去端点才报 `PLUGIN_DEGRADED`」**：`slotProjection` 只看启停不看降级。内置件降级只有一条路且纯函数实跑通：停光某内核件的依赖方 → 停内核件（闸放行）→ 重开某个依赖方（闸放行）→ 它变降级、页签仍在。今天设置页没有内核件开关，界面正常操作走不到；第三方件进来或手改 ui-state 才遇到。
3. **12 件工作台里只有 8 件有页签**：分析在右栏、导入导出在宿主动作位、生图与识图／知识库在设置区。
4. **「不可停」是推导态不是类属性**：Agent 运行时、事实内核、存储内核永不可停（被永远启用的 Agent 栏、库管理依赖）；推演引擎、媒体引擎、正文内核、文本内核在依赖方全停后可停。宿主组合面写死不可停。
5. **内置 21 件没有任何自带设置项**：12 件工作台都只有 `settingsHint`，生图与识图、知识库另有 `settingsJump: engines`；它们的真配置卡在「引擎与存储」里且受模块启停控制显隐。
6. **启停按库记**（库内 ui-state）；没开库时 `/api/plugins` 不带按库状态。
7. **「事前解释」与「接口报错」不同源**：`uiStatePut` 的闸只吃内置 21 件，投影吃的是含本机覆盖／迁移剔除／套件状态的有效清单；前端还把闸的报错吞掉。
8. **套件货架读的是 `/api/suites`**（带设置值与表单），`/api/plugins.plugins[]` 不带；本机模块区自己再 fetch 一次并局部覆盖 `state.plugins`。
9. **显示名**：页签栏其实已读投影里的清单名；命名表（`public/views/registry.mjs` 的 `NAMING_TABLE`）里的页签列是留着的第二份，被门禁 S2.5／S2.9／S4.1 与 `test/naming.test.mjs`、`test/os172Naming.test.mjs` 当对照真源用；表的其他列（目录名、日志模块名、契约域、MCP 前缀）后端约 28 个文件在用，不能动。
10. **工程约束**：`app.js` 上限 10,500 行（现 10,107，只降不升）→ 新界面落 `public/views/`；`views/*.mjs` 互不 import（门禁 S2.2）；`index.html` 令牌区外不许裸色值（S3.1）；数字锚链、C6 测试、`moduleSettingsConsumers` 测试、现有测试只增不删。

## 6. 出口条件（七句）

1. `/api/plugins` 是治理台、全部套件、本机模块三处的唯一取数口，前端只有一个装载函数，`state.plugins` 不再被局部覆盖。
2. 治理台里投影中的每一件都有卡：供给、依赖逐条（带供给方与版本）、谁依赖我、设置指路、停用影响；内核件与宿主组合面只读，并能解释为什么停不了（含二跳连锁）。
3. 能力图由投影算出来，点节点只亮它的正反向依赖并定位到卡片；底座能力折叠成一条说明。
4. 停用工作台先出确认条（影响面按位置生成），确认后各处照投影即时变化；闸拒绝时如实显示原因；没开库时开关置灰。
5. 依赖缺失的工作台在页签、右栏入口、顶栏动作、设置区一律灰显＋悬停列出缺失项，直接进视图给说明页——不再有「页签照常在、点进去才报错」。
6. 前端命名表不再保存模块页签名的第二份；三名一致的门禁与测试改拿 manifest 的显示名核对，强度不降（反证有效）。
