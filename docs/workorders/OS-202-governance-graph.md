## 目标

治理台主区顶部加一张**能力图**（内联 SVG）：节点是投影里的全部模块（内置 21 件＋本机模块），三类着色；有向边是能力依赖（依赖方 → 供给方）；全员依赖的底座能力折叠成一条说明。点任一节点，图中只亮它的正反向依赖、其余压暗，并展开、滚动定位到对应卡片。可收起。这是「谁依赖谁」第一次画给用户看。

## 任务

### 1. 纯函数 `capabilityGraphSvg(graph, modules, { selected })`

放 `public/views/governanceViews.mjs`（零 import，具名导出供 Node 测试），输入 `moduleGraph` 与 `modules[]`，输出内联 SVG 字符串。

- **节点**＝投影里的全部模块，不是写死的 21 个；三类着色走 `--cat-kernel`／`--cat-workbench`／`--cat-host`；本机模块加「本机」小标；已停用画虚线框；降级描边用 `--warn`。每个节点带 `data-id`、`data-status` 与 `<title>`（名称 · `id@v版本` · 状态）。
- **布局由数据算**，不写死坐标：自上而下三段——工作台（每行至多 6 个，多了换行）、宿主组合面（靠右竖排）、内核件（最下一行，多了换行）；同类内按 id 稳定排序；同一输入两次输出逐字相同；任意两个节点的矩形不相交。
- **边**＝`graph.edges`（`from` 依赖方 → `to` 供给方），箭头画在供给方一端（`<marker>`＋`marker-end`），画在节点下层；指向底座（`to === 'base'`）的边不画，折进底部说明条；默认描边用 `var(--line)`（要看得见）。每条边带 `data-from`／`data-to`／`data-capability` 与 `<title>`（「A 依赖 <能力> ← B」）。
- 颜色只用 `var(--*)`；字号走 class 的 `--ui-fs-*`，不在属性里写像素；名称一律转义。

### 2. 选中

点节点＝选中该件：与它相连的边用强调色加粗、相邻节点保持、其余节点与边压暗；同时展开并滚动到对应卡片（闪一下强调）。再点一次取消选中。图与卡片共用同一个选中态——点卡片行，图里也亮。已停用模块的依赖边画虚线（它当前不活跃），不参与高亮。

### 3. 图例与底座说明条

图例三类＋一句「箭头＝能力依赖（依赖方 → 供给方）」。底部说明条由 `graph.base` 生成：「底座 · base.write / base.naming / base.contract ＋ 装载协议 · 能力图 · 契约壳 · 物理写管道（全员依赖，图中略）」——能力 id 与依赖方数取自数据，后半句是固定说明。`graph` 缺失时整块不出，不留空框。

### 4. 收起

「收起／展开能力图」按钮，收起后只留标题行；开合状态记在视图内存里即可（不是内容性数据）。

## 测试（`test/governanceViews.test.mjs` 加例）

- **布局**：内置 21 件 → 21 个节点；坐标全为有限数；任意两节点矩形不相交；同输入两次输出逐字相同；每条非底座边都带 `marker-end`，且 `from`／`to` 都是存在的节点。
- **选中**：选 `fact` → 高亮边 14 条、相邻节点 10 个、压暗节点 10 个；选 `roleplay` → 高亮边 4 条；再取消 → 无高亮无压暗。
- **状态**：本机模块进图并带「本机」；已停用节点 `data-status="disabled"`，它的依赖边是虚线；降级节点 `data-status="degraded"`。
- **说明条**：列出三个底座能力 id 与依赖方数（4／2／5）；`graph` 缺失 → 不出能力图块。
- **转义**：名称含 `<`、`"` 时被转义。
- **源码**：视图仍零 import；`app.js` 行数不增。
