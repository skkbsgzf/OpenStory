# D6 · NovelPedia 与世界书的关系判定（2026-11-28 作者口径修正）

> 作者原话：「D6 的 NovelPedia 似乎有个误区，这个本质上和目前的世界书插件是同源的，
> 任何一本书都可以被拆成世界书，现在有啥问题，具体补充。」

## 一、作者判断成立，ADR 0001 已把这点钉过

| 事实 | 证据 |
|---|---|
| `pedia/v1` 与 `fact.data/v3` **同源同质** | ADR 0001 §二 F2：`vocabulary.js:4-5,26-32` 把 NovelPedia 的 `pedia_schema.json` 与本仓 fact 词表写成**同一条出处链**；v3 相对 v2 只做减法（F3），不改 id 输入、不改分层 |
| 仓内 domain 真源文件自己就叫 `pediaSchema.js` | ADR 0001 F5：「文件名里的『pedia』正是 pedia/v1→fact 谱系的活化石，内容就是 fact 的 domain 真源」 |
| 校验闸只认这一套 | F4：`schema` 不是 `fact.data/v3` 且不在 legacy 清单即 `SCHEMA_MISMATCH` |
| 因此 | **NovelPedia 数据 = fact 数据**，导入导出走 `fact.data/v3` 就是走同一条路（ADR 0001 §三a） |

所以 D6 原来的表述「拿一本真书跑导出→导入回环」**问错了问题**——它假设 NovelPedia 是外部格式需要适配。实际上适配器 `pediaAdapter.mjs` 只是字段投影（纯函数），数据本来就是同源的。

## 二、真正的缺口在哪（不是数据同源，是产品路径没打通）

「任何一本书都能被拆成世界书」在**数据模型上成立**，但**产品上要三步全齐**才叫「能」：

| 步 | 能力 | 现状 |
|---|---|---|
| ① 书进来 | 整目录导入（`libraryImport`）按章节号分拣；或 `novel_write_chapter` 逐章写 | ✅ 有 |
| ② 拆成事实链 | 从正文抽剧情/人物/设定/关系/伏笔 | ⚠️ **只有 skill 说明书（`skills/fact-extract`），没有一键 API** |
| ③ 事实链进世界书 | fact 条目 → `世界书/*.md` 笔记（带双链） | ❌ **没有这个转换**；`referenceNotePut` 要求调用方自己写 md |

**缺口具体是两处：**

1. **`fact-extract` 只是 operate 说明书，不是端点。** 它告诉 Agent「怎么抽」，但抽取本身要靠模型跑——非 MCP 场景（作者自己导一本旧书）没有入口。
2. **fact → 世界书笔记的单向转换不存在。** 现在 fact 条目能进故事源（`/api/fact/entries`）和扮演，但变不成 `世界书/人物/xx.md` 那种可双链的笔记。反过来（笔记→fact）也没有。

这两点其实 `LEGACY-ITEMS.md`【后续可选】里已经记着（「世界书人物单页档案」「故事源大纲双向编辑」同源缺口），只是没和 D6 连起来。

## 三、D6 应该改成什么

**原 D6**：「NovelPedia 真实数据导出→导入回环复验」——问错了，数据同源，回环证明不了新东西。

**新 D6**（拆成两件，都可做）：

| 编号 | 事项 | 能做什么 | 需要作者给什么 |
|---|---|---|---|
| **D6a** | 回环复验降级为「同源性证明」 | 用一本真书（任何格式）跑「导入 → 抽事实链 → 事实链导出 pedia/v1 → 再导入」，证明同一本书在两条格式下事实链一致。**不需要 NovelPedia 软件**，因为格式同源 | 一本真实小说（txt/md 均可） |
| **D6b** | **`fact → 世界书笔记` 导出端点** | 新增 `POST /api/reference/from-fact`：把 fact 条目按层投影成 `世界书/{人物,事件,设定}/*.md`，带 `[[双链]]` 与 frontmatter。这是「一本书→世界书」的最后一步 | 无需素材，纯工程 |

D6b 才是作者口中「任何一本书都能被拆成世界书」真正缺的那一环。

## 四、明确不做

- **不重写 pediaAdapter**：它已经把同源字段投影好了，再写一套是重复。
- **不把 NovelPedia 当外部软件对接**：ADR 0001 已裁定不互认桌面端、不读旧清单；「真书复验」只是拿数据验证，不是接它的产品。
- **不在 MCP 开 absorb**：AGENTS.md 硬规则 4——旧目录迁入世界书只走界面按钮。

## 五、结论

作者判断正确：**NovelPedia 与世界书同源，没有「格式不兼容」问题**。
D6 的真实缺口是 **「fact → 世界书笔记」缺少导出端点**（D6b），以及 `fact-extract` 只有说明书没有可调用入口（可由 D6a 的真书流程顺带验证）。
