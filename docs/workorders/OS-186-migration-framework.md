## 目标

把 OS-172 手写的一次性升级、OS-179 演练里的最小迁移器，抽成**通用迁移器框架**：`from → to` 单向执行、幂等、失败安全阀、全程留 `.history`。以后任何能力升 major、任何改落盘格式的覆盖，都只是写一个迁移器入口。

## 任务

1. **框架**：读 manifest 的 `migrations[]`，在覆盖安装／首启时执行一次；每个迁移器前后都走物理写管道并留 `.history` 备份；迁移标记落 `.openstory/`（或定稿的位置）。
2. **失败安全阀**：迁移器抛错 → 保留原格式数据、禁用覆盖者、报 `MIGRATION_FAILED`，**绝不留半迁状态**（整批原子：要么全成，要么全不动）。验证手段：注入一个中途抛错的迁移器，断言数据逐字节不变。
3. **单向红线**：迁移不可逆（不提供 to→from）；旧数据文件不删，只转换内容。
4. **与 fact 增量 PATCH 的关系**：台账里「fact 增量 PATCH」与迁移器框架同属落盘契约变更——本单只写一段评估（要不要做、与迁移器如何共存），不实现。
5. **测试**：成功路径、幂等（重跑无副作用）、失败安全阀（逐字节不变）、部分失败（批内前几条已写、后一条失败 → 全部回滚）、迁移后旧读者读不了的如实报错。

## 不做

- **绝不碰作者真库与真实院子**（全部用临时夹具库）。
- 不实现任何具体的 `@3 → @4` 迁移（框架只管跑，迁移器由将来的能力升版自带）。

## 验收

- 全量测试与验收门禁全绿。
- **旧库升级全链路演练**：造一个「上一批格式」的夹具库 → 首启自动迁移 → 读写正常 → `.history` 有备份 → 重启幂等；注入失败 → 数据逐字节不变、覆盖者被禁用、错误可读。全程输出贴报告。
