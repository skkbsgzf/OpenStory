### 一、ADR 0002 `docs/adr/0002-base-constitution.md`

1. **五件清单逐条质询**（进程与网络／装载协议／契约壳／物理写管道／词表）：每件写「为什么它不能是插件」＋一条反例质询（「如果把它做成插件会怎样」）。经不起质询的就降级为内核件，并写明后果。
2. **自举顺序与底座自有 requires**（R2）：零插件状态下底座能做什么；装载顺序（内置内核件 → 能力图检查 → 工作台 → 套件）；底座自己依赖哪些能力、由谁保底供给。
3. **裁定四个开放问题**（规划 §2.9）：
   - storage × genres 边界；
   - jobCenter／events 归属；
   - 套件声明式逻辑的边界（数据驱动 DSL 允许、图灵完备脚本禁止）；
   - naming 双端豁免的归宿。
4. **逐条处置评审意见 R1–R14**：采纳／驳回／改写，各写一句理由。至少要给出结论的：R3（分析引擎归属）、R4＋R5（停用的两种语义与启动失败策略）、R6（套件覆盖不带迁移器）、R7（能力 id 注册表不写死）、R8（路由表静态 vs 热更新）、R9（slot 声明去重）、R11（生图执行器归属）。
5. **裁定反转留痕**（R1）：明文记录本批推翻了「旧库不迁移」「金样不动＝Pinax 互认唯一锚」「桌面端开新库确认」三条，理由是作者把验收标准改为内部代码质量。
6. **状态标注**：本 ADR 在作者过目前标「讨论稿」，过目后改「已裁定」并记日期。
