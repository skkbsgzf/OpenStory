# 拆书采集质量守则

> 底账：4 本实测审计——事件流底座合格（逐字＋7 通道＋段定位＋可溯源 99%），但采集端要了的数据在处理层丢过（实锤），who 缺失 46% 的根因是回包覆盖不足而非提示词。本守则按「采集端 → 处理端 → 架构」三段收口。

## 采集端七守则

1. **单轮扫描记全**：只留一轮扫描，默认大参数模型一轮干完所有活；错漏判定不做在这轮——封装成一致性检测（fact-consistency），全书拆解/改编改写时才全文过。
2. **桶分段保完整章**：一段一段文字放桶里，优先保证完整章节，不做按字数硬切的伪分段。
3. **视角参数**：Agent 扫文章代入**读者身份**，文本本体带视角参数。第一人称叙述时「我爸妈/男友/闺蜜」这类称号本身就是身份，无需赋人名；后续出现真名小名再补全。已知人物表含主角时，无主叙事块 who=主角；判不了填 `narrator`。
4. **known-persons 增量累积**：跨批传递「已知人物」表并注入每批——形同虚设时幻觉 who 高达 38%。
5. **say 带说话对象**：对白事件加可选 `to` 字段，对话网络/权力关系才有原料。
6. **闪回/插叙标 track**：channelHint 加时间线提示或 enrich 层补标，否则时间线把回忆当主线。
7. **权重阈值剪枝**：低权重角色（后文再无回响的随手一提）不建角色文档、跳过对应流程——参数化阈值，按权重做策略剪枝。

## 处理端四守则

1. **回包覆盖度校验**：模型回包没覆盖全部块时，缺哪些块就只重发哪些块；批降到 4 段/调用以内防截断（8 段/调曾致 46% 规则兜底、who 恒空）。bound 目标 ≥95%。
2. **字段要落地**：采集端问了 settings/knowledge/hooks/aka，处理端编译时就要接住——「问了但编译丢弃」是最隐蔽的一类丢失。
3. **死字段不留**：novelty/notes 这类恒空的字段，要么实现要么从产出删掉，不留幽灵字段。
4. **绑漏自检**：bindStats 是体检表——bound/ruleFallback/hallucinated 三个数异常就先查批大小与人物表传递，不要先改提示词。

## 架构守则（缓存池机制）

- **RAG 是硬储存（SSD），data 是快储存（DDR）**：data 每存 N 条（约 3–5 章体量）触发一次 RAG 更新，把 data 内容 flush 进 RAG，同时基于 RAG 知识映射给 data 剪枝、清理、归档，再开新 data 继续闯——最大程度规避长上下文注意力涣散。
- **抽取完阶段性地做 IG（情报网）巩固**：巩固后，后续抽取若命中已有知识，能高效回到 IG 匹配并更新。
- **参数化采集节奏**：短篇（≈2 万字）与长篇（数百万字）的采集节奏、批大小、剪枝阈值不同——先把默认一套做到商用级，不做剪法，参数留口。
- **模板化、工程化拓化**规避长上下文复杂任务的注意力分散：文字塞给模型前先用分词器分拆清理，LLM 只做机械流水线判断，无需思考，整体形成并行流水线。
